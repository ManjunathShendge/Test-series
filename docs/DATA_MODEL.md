# Relational data model

This is the schema specification; SQL migrations in `packages/db/migrations/postgres` and this document evolve together. Storage is PostgreSQL 17 (Supabase in staging/production). UUID identifiers; UTC timestamptz; integer paise for INR; rational/integer-scaled scoring; explicit foreign keys, created_at and updated_at on mutable records. No soft-delete cascade may erase financial/audit history.

## Constraints and indexing

- unique `(question_id, version_no)` and `(test_id, version_no)`; triggers or restricted mutation paths reject frozen version edits.
- `(exam_id,text_hash,normalization_version)` and masked-hash btree indexes; GIN pg_trgm on normalized English stem with exam filtering; benchmark composite btree_gin strategy.
- GIN image hashes; question corpus indexed by exam and approval/source state; exclude same logical question during historical matching.
- Payment uniqueness includes provider + environment + transaction/token identity. Event uniqueness alone is insufficient for economic effects.
- Unique entitlement source per order item; multiple grants may overlap. Refund revokes only that source.
- Ledger source-event uniqueness and immutable grants; allocation table changes do not mutate ledger rows.
- FK/constraint checks on item scope, nonnegative line amounts, valid option membership, section positions and date intervals.
- App role cannot UPDATE/DELETE ledger or audit. Separate migration role; protection tests use actual application privileges.
- Sensitive blobs/tokens encrypted; audit snapshots exclude secrets/content/KYC. Retention and deletion policy finalized before production.

## Implemented M0 baseline (19 November 2026)

Migration `001_storage.sql` installs `pg_trgm` and `btree_gin` and implements storage primitives only, not the domain services. Identifiers are `uuid`, times `timestamptz`, money `bigint` paise, payloads `jsonb`:

- `bootstrap_state` with schema version 1, checked by readiness.
- `users` (no password column: Firebase owns credentials), `roles` (student, examiner, reviewer, ops, finance, super), `user_roles`, `sessions` (hashed token references).
- `billing_orders` (integer paise, INR only, unique idempotency key), `billing_events` (unique per provider event), `ledger_entries` (unique source event; update, delete and truncate blocked by triggers).
- `audit_events` (update, delete and truncate blocked by triggers).
- `jobs` (deduplication key, `FOR UPDATE SKIP LOCKED` claims, leases with recovery of expired leases).
- `schema_migrations` (name and checksum, maintained by the migrator).

Row-level security is enabled on every public table except `schema_migrations`, with a single `exam_service_access` policy for the API and worker roles; the migrator reapplies it after each run. Authorization still lives in API services; RLS is a second barrier, chiefly against Supabase's Data API roles. Binary file content is not stored in the database; object storage is chosen when uploads are built.

The identity and commerce workflows that must use these tables are M1 and M9 work; the M1 schema will extend or replace these primitives to match the specification above. The idempotent local/test seed inserts a synthetic infrastructure marker, not a user or paper. Locally the migrator owns the schema and the API/worker roles have row access only (`docker/postgres/init`); authorization is still enforced in API services. Production role provisioning remains a deployment responsibility. The superseded Prisma bootstrap is preserved in `docs/archive/postgres-bootstrap/`.

## Attempt engine (M7, 24 November 2026; migration 019)

- `student_attempts` gains `session_epoch` and `ack_seq`; a unique partial index allows one in-progress attempt per student. `active_session_token` stores a SHA-256 hash of the session token, never the token.
- `student_attempt_sections` (attempt, section, order, duration, opens_at, closes_at, closed_at): the server's windows. Whole-test timing opens every section together until the deadline; sectional timing opens one at a time, and finishing early closes it without carrying time over. Students read their own rows only.
- `student_attempt_events` (attempt, epoch, seq, payload, accepted, reason, received_at): append-only log of every received event, including rejected late ones with the reason (`time_up`, `section_closed`, `attempt_closed`, `unknown_question`).
- `protect_answer_authority` trigger: answers change only through the API functions, inside an open window, with a valid option.
- Scoring uses the latest corrected key; `sectional_scores` is keyed by section; ranks and test statistics count first attempts only.
