# Phase 0 spike evidence templates

Create `S1-trigram.md`, `S2-rendering.md`, `S3-infrastructure.md`, `S4-store-billing.md` when each experiment runs. They do not exist as completed findings today.

| Spike | Experiment | Required result |
|---|---|---|
| S1 | ~200 labelled same-exam EN/HI exact/near/variant/unrelated pairs | Dataset provenance, precision/recall by language, false positives, high/mid thresholds, indexed latency, fallback decision |
| S2 | Real mid-range Android and iOS, cold/warm bilingual grouped math/image paper over shaped 4G | Device/build/network, test-ready timings, local-save latency, size/font costs, WebView accessibility and alternative if needed |
| S3 | Candidate India-region host/DB/object store with actual worker workload | Current quote/terms, availability, residency, extensions/pool compatibility, resource limits, backup/restore result and upgrade budget |
| S4 | Apple/Play sandbox fixed-tier product purchases with killed client and duplicate/out-of-order notifications | Product type suitability, exact item/account correlation, same-tier concurrent purchase handling, restore after consumption, refund, acknowledgement, approval risks and chosen mapping |

Each finding contains date, hypothesis, setup/versions, reproducible steps, observed data, limitations, decision/owner and affected docs. Failed experiments are useful evidence; never mark a spike complete with a plan alone.
